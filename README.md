# Witchy Party · 女巫的聚会

女巫们在下午茶集会上玩的一场炼金游戏。支持本地或单实例服务器运行、2–8 位真人与 AI 混合参与、3 / 5 / 10 次出牌、自由构想材料，以及投料和连锁合成演出。金币、随机判定与结算由服务端控制，进入游戏前需要访问邀请码。

## 启动

需要 Node.js 22.12+ 和 npm。

首次运行先将 `.env.example` 复制为 `.env`，填写自己的 DeepSeek 配置；已有 `.env` 时保留它。首次生成邀请码后保存输出的 UUID，随后发给朋友：

```sh
npm install
npm run invite:generate -- --write-env
npm run dev
```

打开 http://127.0.0.1:5173，输入生成的邀请码。创建普通房间后，可添加 AI 女巫，也可让其他玩家通过房间码加入。访问邀请码用于进入网站，房间码用于选择对局，两者不同。每个标签页单独保存房间身份；刷新后自动恢复原来的玩家、材料和当前演出进度。以后启动只需 `npm run dev`，不必重新生成邀请码。

首页仅保留居中的创建／加入卡片，标题为“女巫的聚会”，副标题为“今天来点魔法”，坩埚从卡片顶部中央探出。首页背景与操作教程留待后续制作；房间内仍保留连接状态和规则入口。

运行打包版本：

```sh
npm run build
npm start
```

打开 http://127.0.0.1:3001。默认仅监听本机；本项目未创建或发布托管站点。

## 访问邀请码

`npm run invite:generate` 使用 Node 的安全随机数生成 UUID v4，并输出对应的 SHA-256。默认只输出；加 `-- --write-env` 才会将哈希写入本地 `.env` 的 `INVITE_CODE_SHA256`，保留其他配置。原始邀请码不会写入项目文件，也不会打包进浏览器代码。

浏览器将输入去除首尾空白、转为小写，再计算 SHA-256。只有服务端验证成功才把 64 位十六进制哈希保存到 `localStorage` 的 `witchy-invite-hash`；不保存原始邀请码。再次打开网站时先验证已保存的哈希，通过后才连接游戏。网络故障保留凭据并允许重试；凭据被拒绝时返回邀请码页面。

所有 `/api` 请求先验证 `X-Invite-Hash`，包括 `/api/access` 与 `/api/health`。WebSocket 在升级连接前验证子协议中的凭据，且每条游戏消息都再次验证顶层 `inviteHash`，然后才处理创建、加入、恢复、操作或离开。凭据不放在 URL 中。只有用于加载邀请码页面的 HTML、脚本和样式等静态资源公开可读；它们不包含有效邀请码或哈希。服务端未配置有效哈希时拒绝游戏访问，不会自动变成免密模式。

这是供朋友共享的通行证，保存的哈希本身也具有访问权限。服务端配置值不要放到 `VITE_*` 变量或前端源码中。更换邀请码时重新生成、更新服务器的 `INVITE_CODE_SHA256` 并重启，旧邀请码和旧浏览器凭据随即失效。重启也会清空当前内存中的房间。

## AWS 与 Cloudflare

部署时使用打包后的 Node 服务：安装依赖 `npm ci`，构建 `npm run build`，然后 `npm start`。服务会在同一个端口提供页面、API 和 WebSocket，不需要把 Vite 开发服务部署到公网。服务端保留以下环境配置：

| 配置 | 说明 |
| --- | --- |
| `INVITE_CODE_SHA256` | 生成器输出的哈希；与朋友持有的邀请码对应，必填 |
| `DEEPSEEK_API_KEY` | 模型服务密钥；仅配置到服务器 |
| `HOST` | 同机 Cloudflare Tunnel 可用 `127.0.0.1`；需要从外部代理或容器网络连接时用 `0.0.0.0` |
| `PORT` | 默认 `3001`，与代理的回源端口保持一致 |

HTTPS 由你的 Cloudflare 配置处理。浏览器从 HTTPS 页面访问时自动使用 `wss://`。将同一域名下的页面、`/api/*` 和 `/ws` 转发到这个 Node 服务，并保留原始 `Host`、`X-Invite-Hash` 以及 WebSocket 升级和子协议请求头。`/api/*` 与 `/ws` 不要配置强制缓存；服务端的 API 响应也带有 `Cache-Control: no-store`。Cloudflare 需要保持 WebSockets 开启，参见其[官方说明](https://developers.cloudflare.com/network/websockets/)。

目前房间与重连状态保存在单个 Node 进程内，部署时运行一个实例，不要直接使用多进程集群或多个副本。通过常驻进程管理或容器运行这个实例；进程重启后玩家需要重新创建房间。

## DeepSeek

在 `.env` 中填入自己的服务端配置后重启服务器（已有邀请码哈希时保留该项）：

```dotenv
DEEPSEEK_API_KEY=填入有效密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

兼容接口可修改地址和模型，服务端在根地址后追加 `/chat/completions`。密钥仅在服务端读取；`.env` 已忽略，不会打包进客户端。界面的“已配置”表示服务器具备密钥，实际鉴权与网络错误会在操作时显示。

未配置密钥时可创建和加入房间，但不能添加 AI 或开始比赛。游戏不提供离线替代模式。精确命中本轮已知材料时复用价格，其余定价、合成命名与 AI 选材均通过配置的模型接口完成。真人操作失败可重试；AI 的网络或接口故障表现为该女巫掉线，详细错误保留在本地日志中。

## 游戏规则

1. 每位玩家在整场开始时获得一次 **20,000 金币**。金币跨轮继承，分数就是当前金币。选择 3 / 5 / 10 轮，表示仍在场玩家最多出牌的次数。
2. 每轮随机排列座次。所有仍在场玩家同时秘密构想材料，最多成功召唤三张候选卡，从中选择一张准备。全员准备前可以取消准备；查看候选卡不花金币。
3. 全员准备后锁定投入，并各扣除一次材料价格。必要的反应计算完成后，直接按本轮座次播放投料光点飞入、两份材料融合和新产物出现，没有单独的全员亮牌页面，也没有人为的计算等待倒计时。同次投料还会继续反应时，中间材料卡停留约 1 秒；单次投料或整串反应结束后停留约 1.5 秒，再进入下一段。
4. 合成消耗两种原料并产生新材料，新产物可继续反应。最终锅中所有现存材料的价格合计为本轮金币奖励。合成不额外收费。
5. **本轮原始投入价格最高的人获得整锅奖励**，并列最高时由服务器随机决定；合成后的价格不会改变原始投入排名。
6. 允许透支。先计算 `结算金币 = 上轮金币 − 本轮材料价格 + 本轮奖励`，再判断失败。结算后金币仍小于或等于零的玩家，金币和分数清零，余下轮次旁观；拿到奖励后恢复正数即可继续。
7. 只剩一位未失败且未离场的玩家时，提前结束并获胜。正常打满所选轮数后比较最终金币；最高金币相同的玩家并列获胜。终局结果不会因玩家随后离场而改变。
8. 全部投料与反应演出结束后发放奖励，先展示本轮得主：头像放大至屏幕中央，配以金色辉光，下方显示其原始投入材料和价值。点击遮罩或“点击查看排行榜”后展示当前金币和本轮变化。下一轮继承金币。没有旧版的多圈投料、继续／退出决定、喝药演出或历史记录页面。

准备阶段只有本人可见自己的候选材料；材料名称、价格和归属在各自的投料演出中展示，合成结果在对应反应演出中出现。材料描述中的改价指令会被拒绝；拒绝不会消耗金币或占用成功召唤名额。

品质区间为白色 `[0,10)`、绿色 `[10,50)`、蓝色 `[50,200)`、紫色 `[200,2000)`、金色 `[2000,10000)`、红色 `[10000,+∞)`。红色材料不参与后续合成。材料名称进行 NFKC 标准化后精确匹配；同轮同名材料价格一致。无序原料对、原料价格和本次抽中的价格区间相同时，可以复用合成命名结果。

反应概率直接使用材料向量的基础距离概率 `min(1, 向量距离 / probabilityDivisor)`，不再额外平方。相同名称的向量距离为零，红色材料仍不反应。

## 演出与 AI 记忆

全部模型结果准备好后直接进入演出。投料动作默认 1,800 毫秒，反应动作默认 2,400 毫秒。投料后紧接反应、或产物还将继续连锁反应时，动作后静止停留 1,000 毫秒；没有后续反应的投料、以及一串反应的最后产物，完成后静止停留 1,500 毫秒。材料名称、价格和归属在停留时保持清晰，段与段之间不等待模型。光点从对应头像飞向材料卡位，两份原料随后消散并汇聚为新产物，连锁反应依次展示。

动作与阅读停留由服务器统一计时；最后一个产物停留完整 1.5 秒后才结算。刷新从当前动作或停留进度恢复，期间不能提前开始下一轮，也不会再次扣费。可在规则配置或环境变量 `DEPOSIT_MS`、`REACTION_MS`、`HOLD_MS`、`CHAIN_HOLD_MS` 中分别调整两种动作时长、完成后的停留与连续反应间的停留时长；未单独指定连锁停留时，它不会超过完成停留时长。系统开启减少动态效果时保留材料变化与相同的结算顺序，弱化运动。

房间聊天已移除，包括大厅与局内入口、服务端消息收发、AI 聊天请求和聊天上下文。旧客户端发送聊天消息会被服务端拒绝，AI 不读取或生成公开对话。

本轮得主演出以最后一张材料画面为背景，覆盖磨砂玻璃遮罩；获胜头像约用 1.2 秒从原席位移动、放大至视口中央，周围呈现大范围金色柔光。文字显示的是得主本轮原始投入的材料及价格，而非合成产物或整锅奖励；最后一轮也仍先展示本轮得主。演出不会自动切到排行榜，每个客户端点击后才查看。未确认时刷新会恢复该演出，已经确认后刷新不会重播。没有实际投料的提前结束直接展示结果。红色卡牌的外扩光晕缩小，获胜者的金色光晕使用更大的渐变范围。

七位 AI 女巫有独立的选材人格。每次备料时，AI 先构想材料并获得服务器的实际报价，再根据金币、人格和策略决定继续询价或选定已有候选；最多成功询价三份，也可以提前选定。选卡由 AI 决定，不默认使用第一张或最贵的一张；只有全员准备后才扣除所选材料的价格。

每个房间实例的每位 AI 各自保存人格、显式策略、最多 12 次近期询价／选择、10 轮公开结算摘要，以及最多 256 条带轮次和来源的真实价格记录。价格记录包括自己的成功报价（包含未选中的候选）、往轮公开投入，以及公开反应链中的全部产物（包含后来被继续合成的中间产物）。其他玩家未公开的候选不会进入该 AI 的记忆或选材请求。AI 可以参考这些价格构想可能更值钱的新名称，也可以复用见过的材料或参考材料；旧报价只是历史参考，复用旧名称仍须在本轮询价并占一个候选名额。

选材使用受约束的 JSON 询价／选择循环。服务器验证动作和候选归属，只接受实际报价，忽略模型自行填入的价格。同轮重复名称、材料拒绝或无效选择会给 AI 反馈，并计入每轮最多 8 次决策的上限，但不占成功候选名额。已有三份候选或剩最后一次决策且已有候选时，只允许选择；用尽决策次数仍未选定则按 AI 掉线处理。不同 AI 并行备料，同一 AI 的步骤依次执行；真人刷新或短时断线不会重置本轮预算。

策略和记忆不发送给其他玩家。原始 `reasoning_content` 只保留在日志，不作为下次请求的记忆；每次请求重新提供结构化状态、报价和简短策略。过期结果不能覆盖新记忆，房间删除时中止请求并清理记忆。

## 提示词与配置

`config/prompts/` 将每次模型请求的系统提示词固定组装为四段：**任务背景、角色设定、任务描述、输出约束**。这些文本在每次调用时重新读取，修改后下一次请求生效。

| 内容 | 文件 |
| --- | --- |
| 游戏背景与统一规则 | `background.txt` |
| 定价／合成系统角色 | `character-alchemy.txt` |
| AI 女巫角色 | `character-witch.txt` |
| 三项任务描述 | `task-price.txt`、`task-synthesize.txt`、`task-imagine.txt` |
| 通用及各任务输出格式 | `output-format.txt`、`output-format-*.txt` |
| 七位女巫的名称与人格 | `witches.json` |

`witches.json`、`config/materials.json`（18 种参考材料）与 `config/rules.json`（初始金币、候选次数、动画时间、品质区间等）在启动时读取，修改后需要重启服务器。

每次实际合成先由服务器抽取价格区间。将原料按价格 `p1 ≤ p2` 排序，取 `pv1 = log10(p1)`、`pv2 = log10(p2)`，分别除以 `pv1 + pv2` 得到 `npv1 ≤ npv2`；抽取独立的 `r ∈ (0,1)`，按以下区间决定产物的合法整数价格范围：

| 随机数区间 | 产物价格范围 |
| --- | --- |
| `r < npv1` | `0` 到 `p1 − 1`，低于较便宜原料 |
| `npv1 ≤ r < npv2` | `p1` 到 `p2`，包含两端 |
| `r ≥ npv2` | `p2 + 1` 到单张材料价格上限，高于较贵原料 |

普通正价保持 `log10(价格)`；零价按 `log10(1)=0` 处理。若两项对数之和为零，则权重各为 `0.5`。价格下限为零，零价的低档范围退化为 `[0,0]`；达到价格上限时，高档范围退化为上限本身。相同原料价格时，中间随机数区间长度为零。

合成命名请求提供两份按价格排序的原料、各自价格、`inputTotal` 和 `priceConstraint`。炼金 agent 必须先构思符合抽中价位的名称，再由 DeepSeek 在同一个闭区间内决定具体价格；产物估价也收到 `synthesisInputs` 和相同的 `priceConstraint`。原料总价不再附带保值或增值倾向。

服务器会拒绝越界价格，不会截断模型价格或改写已有同名材料的价格。若命名撞到区间外的已知材料，需要重新命名。每次反应的抽签在请求前保存；失败重试复用原区间和已成功的命名，不重新抽签，也不重复扣费。连续反应的每一环独立抽签，抽签结果记录在本地房间日志中。

AI 的询价与选定决策默认开启低强度思考，定价与合成使用非思考模式。设置 `DEEPSEEK_BOT_THINKING=disabled` 可关闭 AI 女巫思考，修改环境配置后需要重启。

## 连接与房间生命周期

真人断线后头像显示“掉线”，保留默认 30 秒重连时间；及时恢复可继续原进度，不重复扣费。超时或主动离开后确认离场；备料时尚未锁定的材料不会代为投入，全员准备后已锁定付费的材料仍完成反应和结算。房主离场会移交给在线真人。AI 失败后停止其后续自动请求。

最后一位真人断线后，房间也等待 30 秒；有人回来则取消删除，超时删除房间并中止请求。AI 不会保活无人房间。可通过 `RECONNECT_GRACE_MS`、`HEARTBEAT_INTERVAL_MS`、`HEARTBEAT_TIMEOUT_MS` 调整宽限与连接检查时间。

## 本地日志

新建房间后，在 `logs/rooms/` 保存同名的可读 `.log` 和结构化 `.jsonl` 日志，包含房间实例、玩家、调用编号、耗时、请求数据、模型实际返回的推理与最终内容、解析结果、缓存和错误。原始推理未返回时明确标记，不生成替代内容。

```sh
npm run logs
npm run logs -- 房间码
```

日志在服务器重启后仍保留，仅限本地文件，不通过网页接口公开。密钥与认证字段不会写入日志，目录已加入忽略列表。可通过 `ROOM_LOG_DIR` 改变路径，或设置 `ROOM_LOG_ENABLED=0` 关闭。

## 验证

```sh
npm test
npm run build
node scripts/smoke.mjs
```

自动化测试覆盖游戏规则、透支结算、随机顺序、反应概率、演出时间线、隐私、缓存、失败重试、关闭聊天、AI 多候选选材、实际报价学习与私有记忆、决策次数上限、可编辑提示词，以及真实 WebSocket 的多客户端鉴权、重连、掉线、空房删除和完整多轮比赛。模型调用使用本地接口替身，不消耗真实 API 额度。

`scripts/smoke.mjs` 自动构建并启动独立的本地测试接口和临时游戏服务器，用 Edge 的桌面与手机窗口完成真实浏览器三轮对局，验证刷新、金币继承、准备后直接演出、动作后停留、排行榜和终局。报告与截图写入 `artifacts/smoke-*`。它不会使用 `.env` 中的真实模型服务。`node scripts/animation-smoke.mjs` 在本地预览上用确定性场景验证光点飞入、连续两次反应、1 秒连锁停留与 1.5 秒完成停留、停留中刷新和手机布局，不调用真实模型。

旧的 `results-smoke.mjs`、`decision-smoke.mjs`、`red-visual-smoke.mjs`、`ai-room-smoke.mjs` 以及 `artifacts/coins-ui-qa.mjs` 针对早期流程，不作为新版验收入口。`evaluate-synthesis.mjs` 是可选的真实命名实验，运行它会消耗配置的 DeepSeek API 额度。

房间和 AI 记忆保存在服务端内存中，服务器重启后清空；没有账号、跨服务器同步或持久化战绩。单张材料价格上限为 10 亿金币。
